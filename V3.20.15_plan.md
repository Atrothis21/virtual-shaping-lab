# V3.20.15 Plan - Compositional Agent Hardening and Single-Path Enforcement

## Objective
Harden the compositional agent into a thin orchestrator over observation + learner + policy seams with an explicit typed public interface (`observe`, `predict`, `act`, `learn`, `advance_internal_time`), then enforce single-path agent execution with blocking CI and closeout documentation.

## Slice 3 - Remove Duplicate Agent Execution Paths
### Scope
- Remove runtime shortcuts and fallback branches:
  - update-only fallback paths
  - direct observe/act helper shortcuts in runtime seams
  - phase-level ad hoc action selection once policy seam is present
  - hidden learning inside pre-outcome convenience step wrappers
- protocol-side computation of agent internal error/update terms
- agent-side protocol state mutation
- Keep explicit compatibility bridges only when required, with expiry notes.

### Implemented (this pass)
- Consolidated active test-runtime stepping onto one compositional path in:
  - `virtual_shaping_lab/vsl/rollout/harness.py`
- Removed duplicated phase-local orchestration calls to individual adapters inside harness step flow:
  - direct `RuntimeObservationAdapter.step(...)` pre/post calls in harness loop
  - direct `RuntimePolicyAdapter.step(...)` action selection branch in harness loop
  - direct `RuntimeLearnerAdapter.step(...)` learning branch in harness loop
- Replaced with single orchestrator-mediated path:
  - pre-outcome via `CompositionalAgent.pre_outcome_step(...)`
  - post-outcome via `CompositionalAgent.learn(...)`
  - time progression via `CompositionalAgent.advance_internal_time(...)`
- Kept compatibility bridge in constructor:
  - existing adapter injection remains supported, but is now funneled through `CompositionalAgent`
- Preserved rollout metadata surfaces (observation/policy/learner payload blocks) while removing duplicate execution wiring.

### Commit
- `refactor(v3.20.15): remove duplicate agent execution branches`

## Exit Criteria
- Agent runtime execution is a thin orchestrator over canonical observation, learner, and policy seams.
- No duplicate agent execution shortcuts remain in active runtime paths.
- Composition legality is validated before instantiation/materialization.
- Public interface preserves causal split:
  - pre-outcome (`observe/predict/act`)
  - post-outcome (`learn/advance_internal_time`)
- Experiment provides outcomes only; agent computes internal errors/updates only.
- CI blocks regressions back to multi-path agent execution.
- Architecture note and PR checklist provide auditable closeout evidence.
